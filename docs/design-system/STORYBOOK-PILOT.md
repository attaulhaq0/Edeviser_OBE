# Real-source Storybook pilot — component evidence, not route approval

**Scope:** Eight curated stories for the actual `StatePanel` (loading, empty, error, partial, permission and one strictly local action) and `PCard`/`SectionHeader`/`PageHeader` compositions. The stories import canonical production pattern/barrel exports and one real CSS graph. They do not copy or reimplement those components, connect academic/tenant/AI data, simulate a successful write, or add a second editable token catalog. The [component catalog](./catalog/README.generated.md) remains the documented source-derived API pilot; Storybook's evolving index/manifest is NOT a stable general agent manifest.

**Dependencies:** `storybook`, `@storybook/react-vite`, `@storybook/addon-a11y` are exact **10.6.0** development pins with lockfile integrities, reviewed MIT packages. [Official React–Vite requirements](https://storybook.js.org/docs/get-started/frameworks/react-vite) state React≥16.8 and Vite≥5 (this app is React18/Vite6). The [accessibility addon](https://storybook.js.org/docs/writing-tests/accessibility-testing) provides an exploratory panel; it is not a substitute for automated scene tests or manual assistive-technology review. Dependencies were installed in the isolated frontend branch with lifecycle scripts disabled; no new production import was introduced.

`.storybook/preview.tsx` imports the **real** `src/index.css`, initialized EN/AR i18n and `applyDirection`; toolbar globals simulate light/dark and high-contrast HTML classes plus normal/20px/32px root text (32px is 200% *text*, not a browser-zoom simulation). They are rendering controls **only**. The real ThemeProvider/LanguageProvider use `useAuth` and profile-persistence hooks; the real AccessibilityPreferencesProvider refuses to mount without the AuthProvider ownership bridge. None is mounted or faked here. No Supabase client, router, analytics, service worker, personal data, `.env.local` or live schema is needed. `.storybook/main.ts` restricts stories and uses an empty env directory with a STORYBOOK-only Vite prefix. The build output lives under ignored `test-results/storybook-pilot/`; do not publish/deploy it, treat it as a reviewed screenshot baseline, or confuse it with the existing DSH Web GUI.

```sh
npm run check:storybook:pilot
npm run build:storybook:pilot  # static build, ignored local artifact
npm run test:storybook:pilot   # only after that build; closed-network loopback Chromium
```

The 120-scene bounded browser fixture validates the built index has only the eight selected stories, actual EN/AR root language/direction, light/dark and both contrast settings, five StatePanel semantics, static heading hierarchy, local-only keyboard action, 320px/root20 and **320px/root32 (200% text)** plus1280px/root16 reflow, positive 44px action geometry and visible text bounds at root32, zero external requests/page errors and **32 scoped axe WCAG2.1-AA runs** on representative error and extended reading stories. Arabic extended reading scenes also require an actual loaded Noto Sans Arabic FontFace and a matching computed family; readiness/face status is bounded delivery evidence, NOT human image inspection or proof of every rendered glyph. The test does **not** accept missing stories, missing translations, unexpected redirects, horizontal overflow or external network requests. It does not render every application route/state, assert a customer CSS aesthetic, prove auth-owned preferences, inspect images or approve any visual baseline. These remain G04/G05/G08/PR06 ledger tasks.

The Storybook [toolbar-global](https://storybook.js.org/docs/essentials/toolbars-and-globals) and [interaction](https://storybook.js.org/docs/writing-tests/interaction-testing) docs informed this finite pilot. There is no Vitest-addon automation or public server here; `npm run storybook:pilot` is an optional separate local developer preview and must not be mistaken for the application shell. Product launch and deployment claims remain governed by the [frontend ledger](../audits/frontend-forensic-remediation-ledger.md).

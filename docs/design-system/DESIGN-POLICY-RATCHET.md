# Design policy ratchet — local enforcement, CI bootstrap pending

**Status:** read-only local no-new-candidates comparison, **not** a required CI gate and **not** design compliance. This is a staged part of PR05. The policy kernel/repository adapter already inspect supported authored `src` TS/TSX JSX class/style literals. Generated Shadcn `src/components/ui/**`, test/spec/type files are explicitly excluded; authored dormant components and stories are **included**. Raw CSS, dynamic dataflow, visual contrast, semantic API ownership, CSS-layer/import rules, RTL and live role routes are **not** covered. Do not extend these exclusions to whole roles/domains to get a pass.

```sh
npm run check:design-policy:no-growth -- --base-root <reviewed-clean-distinct-checkout>
```

The caller must provide an actual **trustworthy base checkout** and the current checkout as separate roots. The script reads their sources via the TypeScript AST without importing application code, mutating Git or writing a baseline. It compares per `(file, owner, rule, token)` **multisets** so removing one issue cannot offset adding another copy. It returns exit0 for no-growth (including existing debt), exit1 for growth, exit2 for missing/malformed/unsafe sources or arguments. Output caps introduced identities at five; exact introduced/retained/removed counts and exclusions remain visible. It neither executes nor approves an automatic baseline update. A claimed status from a dirty or self-chosen base has no PR enforcement authority.

At this isolated snapshot, against the untouched `frontend/calm-academic-checkpoint` worktree, the scan found **1130/1132 authored source files**, **7183 → 7138 candidate occurrences**, **0 introduced and 45 removed**. An earlier run had 1 introduced `HeroCarousel` inverse-hover literal. We repaired that actual owner using `--hero-inverse-control-hover` rather than allowing an exception; actual Chromium EN/AR dark hover now computes a white20% surface. Retained **7138** source candidates are not adjudicated bugs, clean design or approved exceptions. The nonportable CSS token intentionally stays in `tokens.css`; the separate 16-color portable DTCG pilot is unchanged.
